CAELESTIA FOR MAC: MASTER BUILD PROMPT
A port of Gabby's Arch Linux + Hyprland + Caelestia desktop to macOS (Apple Silicon)
=====================================================================================

HOW TO USE THIS PROMPT
----------------------
This prompt is sent once. Treat it as the full specification. Every number, color, keybind
and rule you need is written out below, so you can build the whole thing even if no other
files are attached. When the files listed in section 14 are attached, use them to check
your work, especially the screenshots and binds.txt. If this prompt and an attached file
disagree, follow the precedence rules in 0.4.

Work in phases (section 11). Each phase ends with something that builds, runs, and can be
tested. Do not leave stubs or TODOs in shipped code paths. When something truly cannot work
on macOS, say so in docs/LIMITATIONS.md and ship the closest honest substitute. Never fake a
feature.


=====================================================================================
0. CONTEXT AND GOAL
=====================================================================================

0.1 Who this is for
Gabby is an 18-year-old student. Her main machine is an Arch Linux desktop running Hyprland
(Lua config) with the Caelestia shell (Quickshell/QML), on a Samsung C49RG9x 5120x1440 @
119.97 Hz super-ultrawide (output DP-2, scale 1, NVIDIA GPU). Her laptop is a school-issued
MacBook Air M4 with 16 GB RAM. She has an admin account, and the laptop is not MDM-enrolled.
The person running this prompt is her friend, who wrote CatWM (a macOS tiling window
manager).

0.2 Goal
Make any Mac behave and look as close as possible to her Arch setup, so her muscle memory
carries over unchanged: same keybinds (with Super mapped to a Mac key), same tiling behavior,
gaps, borders, corner radii, colors, panels, launcher, and animation feel. It must work on
ANY Apple Silicon Mac running a recent macOS: target macOS 14 Sonoma, 15 Sequoia and 26
Tahoe, minimum deployment target macOS 14. Never hard-code her machine, screen size,
username or paths.

0.3 Product name and components
Working name: "Caelestia for Mac" (bundle prefix com.caelestia.mac; the friend may rename).
  - CaelestiaWM        : window-manager daemon (agent app, no Dock icon)
  - CaelestiaShell     : bar, panels, OSDs, wallpaper, launcher (same process as the WM or
                         a second process; justify the choice in DESIGN.md)
  - Caelestia Settings : the settings app
  - caelestia (CLI)    : IPC client, like `hyprctl` + `caelestia` on Linux
  - CaelestiaSA        : OPTIONAL scripting addition for Enhanced (SIP-partly-off) mode

0.4 Precedence when sources disagree
  1. Gabby's own overrides (caelestia-config/hypr-vars.lua and hypr-user.lua) win.
  2. Then the live runtime dumps (binds.txt, animations.txt, clients.json, monitors.json).
  3. Then the base Caelestia files (hypr/variables.lua, hypr/hyprland/*.lua).
  4. 06-clean-tiling-from-gabby.png is the visual truth for tiling. Screenshots 00 and
     02-05 were taken mid-animation on the ultrawide and look messy (overlapping, half-
     scaled windows). Do NOT copy their overlaps.

0.5 Lessons from a failed attempt ("Riko WM")
An earlier attempt failed with:
  - black tiles (black or empty rectangles where windows or panels should be)
  - ghost overlays (stale border/overlay windows left behind after a window moved, closed,
    or changed workspace)
  - constant flashing (retile loops: the WM reacted to its own move/resize events and kept
    re-laying out)
  - unused screen space (tiles not filling the usable area; wrong math on ultrawide or
    notched screens; off-by-menu-bar errors)
  - missing bar (bar not shown, shown behind windows, or on only one screen)
Each has a named automated test in section 12.2. They are release blockers.

2. ANIMATION SPEC
=====================================================================================

2.1 Speed to time: Hyprland "speed" is in deciseconds, so duration_ms = speed × 100
(global speed 8 = 800 ms). Springs run until settled.

2.2 Curves (cubic-bezier x1, y1, x2, y2)
  default            0.00, 0.75, 0.15, 1.00
  standard           0.20, 0.00, 0.00, 1.00
  emphasizedDecel    0.05, 0.70, 0.10, 1.00
  emphasizedAccel    0.30, 0.00, 0.80, 0.15
  specialWorkSwitch  0.05, 0.70, 0.10, 1.00
  snappy             0.05, 0.90, 0.10, 1.05  (Gabby's; slight overshoot)
  linear             0, 0, 1, 1
  spring "riko"      mass 1, stiffness 180, damping 20 (Gabby's; damping ratio ≈ 0.745,
                     slightly underdamped, a small overshoot)

2.3 Effective animation table (animations.txt = live state; wins over animations.lua)
  global              default, 800 ms
  windowsIn           spring riko, style "popin 80%" (scale up from 80% + fade in)
  windowsMove         spring riko (all tiling moves/resizes)
  windowsOut          emphasizedAccel, 240 ms (scale down + fade)
  workspaces/In/Out   snappy, 320 ms, style "slide" (horizontal, 20 px gap between
                      outgoing and incoming workspace)
  specialWorkspace    specialWorkSwitch, 320 ms, "slidefadevert 15%" (vertical slide of
                      15% of height plus fade)
  layersIn            emphasizedDecel, 400 ms, slide (shell panels in)
  layersOut           emphasizedAccel, 320 ms, slide
  fadeLayers          standard, 400 ms
  fade, fadeDim, border  standard, 480 ms
  borderangle, glowangle, shadowangle: disabled
  Layer rules: launcher = popin 80% + blur; caelestia drawers/background = fade;
  picker / selection / logout / freeze = fade; border-exclusion and area-picker = no anim.
  animate_manual_resizes = false and animate_mouse_windowdragging = false: mouse drags and
  resizes track the pointer 1:1, unanimated.
(animations.lua in the base config has windowsIn emphasizedDecel 400, windowsMove standard
480, workspaces standard 400. Gabby's hypr-user.lua overrides them as above. Keep both as
selectable presets: "Gabby (springy)" default, "Caelestia stock".)
Shell (QML) animations: Material 3 durations × 0.8: small 200→160 ms, normal 400→320 ms,
large 600→480 ms, extraLarge 1000→800 ms, with the emphasized/standard curves.

2.4 Rules
  - All curves and the spring live in one Motion module and are unit-tested on samples.
  - Respect Accessibility > Reduce Motion (switch to short fades).
  - Settings exposes per-animation enable/curve/speed and a global multiplier.
  - In Standard mode, real windows cannot be animated smoothly (each AX setFrame is a
    synchronous IPC round-trip into the app). See 4.2.

3. KEYBINDS
=====================================================================================

3.1 Modifier mapping (decision)
Linux SUPER -> Left Option (⌥L) by default.
Linux ALT   -> Left Command (⌘L).
Linux CTRL  -> Control (⌃).
Linux SHIFT -> Shift (⇧).
Only the LEFT Option and LEFT Command keys act as WM modifiers. Right Option keeps working
normally, so Norwegian characters typed with Option (æ ø å ≈ « » @ £ $ { } [ ] | \ and so
on) still work on her Norwegian ("no") layout. Right Command stays a normal ⌘. Tell the
left and right keys apart with NSEvent/CGEvent device-dependent flag bits
(NX_DEVICELALTKEYMASK 0x20, NX_DEVICERALTKEYMASK 0x40, NX_DEVICELCMDKEYMASK 0x08,
NX_DEVICERCMDKEYMASK 0x10).
Presets in Settings (one click; each preset is just a different modifier map in the
keymap file):
  A. "Option is Super" (default): Super=⌥L, Alt=⌘L
  B. "Caps Lock is Hyper": Caps Lock becomes Super through a user-level `hidutil
     property --set` UserKeyMapping (Caps -> F18, which the WM treats as Super). It is
     reversible, needs no root, and is re-applied at login by our agent (hidutil mappings
     reset on reboot). Alt=⌥L.
  C. "Command is Super": Super=⌘L, Alt=⌥L (for people coming from other Mac WMs)
  D. Custom: pick any physical key for each Linux modifier.
A Super TAP with no other key (Linux "SUPER + SUPER_L" with the release flag) opens the
launcher. Detect it as: Super down, then Super up within 300 ms (configurable), with no
other key or mouse button pressed in between. Never fire it during a ⌥-click, a ⌥-drag, or
while typing an Option character with the left key.

3.2 Single source of truth: keymap file
All binds live in ONE file: ~/.config/caelestia-mac/keymap.toml (shipped default in
Resources/keymap.default.toml). The WM, Settings app, cheat-sheet overlay (Super+K "show
panels" equivalent), conflict checker, and docs/KEYBINDS.md (generated at build time) all
read it. No bind is hard-coded anywhere else; a test fails the build if one is.
Format (example):
  [modifiers]
  super = "lopt"
  alt   = "lcmd"
  ctrl  = "ctrl"
  shift = "shift"
  [[bind]]
  id      = "ws.focus.1"
  keys    = ["SUPER + 1"]
  action  = "workspace.focus"
  args    = { index = 1 }
  flags   = []            # any of: release, repeat, locked, mouse
  linux   = "SUPER + 1"   # original Hyprland bind, for the mapping doc
Flags mean the same as in Hyprland: release = fire on key-up; repeat = auto-repeat while
held (use her repeat delay 250 ms and rate 35/s); locked = also works on the lock screen
(media/volume/brightness only, where macOS allows it); mouse = drag bind.
Hot reload: watching the file re-applies binds within 200 ms. Parse errors show an OSD and
keep the last good map.

3.3 Conflict checker (`caelestia keys check`, also run live in Settings and at startup)
It must report:
  1. Duplicate binds inside the keymap (same chord, two actions).
  2. Clashes with macOS system shortcuts, read from
     ~/Library/Preferences/com.apple.symbolichotkeys.plist (Mission Control ⌃↑, Spaces
     ⌃←/⌃→, ⌃1-9 "Switch to Desktop N", Spotlight ⌘Space, input source ⌃Space and
     ⌃⌥Space, screenshots ⇧⌘3/4/5, Show Desktop, Launchpad, Notification Center,
     Accessibility shortcuts), plus fixed ones that can't be overridden (⌘Tab, ⌘⇧Q,
     ⌃⌘Q lock, ⌥⌘Esc force quit, Power-button chords).
  3. Clashes with common app shortcuts (⌘Q/W/T/C/V/X/Z/S/F/,/.) when Alt=⌘L, with a
     warning that the WM will swallow that chord in every app.
  4. Option-character clashes: for preset A, list each ⌥L+letter bind and the Norwegian
     character it hides when typed with the LEFT Option (e.g. ⌥L+Q = "•" is lost, typing
     it with Right Option still works).
  5. Keys a MacBook lacks (Print, Page Up/Down, Insert, Num Lock, XF86 keys). Each must
     have a Mac alternative chord in the keymap (shown in 3.4).
Output: a table with severity (error / warn / info) and a suggested fix. Settings shows it
with a "Fix" button for each item. For system-shortcut clashes, the fix offers to turn the
macOS shortcut off through symbolichotkeys after backing up the plist (section 10.4), never
silently.

4.1 Two modes
  STANDARD mode (default, SIP fully ON, public APIs only, AeroSpace-style)
    - Window control through the Accessibility API (AXUIElement: kAXPositionAttribute,
      kAXSizeAttribute, kAXMinimizedAttribute, kAXFocusedWindow, kAXRaise), plus
      _AXUIElementGetWindow for the CGWindowID (a private but long-stable symbol that
      AeroSpace, yabai and Rectangle all use; it needs no SIP change).
    - Window discovery: NSWorkspace app notifications + AXObserver per app
      (kAXWindowCreated, kAXUIElementDestroyed, kAXFocusedWindowChanged, kAXMoved,
      kAXResized, kAXTitleChanged, kAXApplicationHidden/Shown) + CGWindowListCopyWindowInfo
      to reconcile.
    - Workspaces are VIRTUAL, all inside ONE macOS Space per display: windows on hidden
      workspaces are moved off-screen (AeroSpace technique: park them so only 1 px stays
      in the display's far bottom-right corner, or on the screen edge farthest from other
      displays), and their frames are restored on switch. Native Spaces are left alone.
      Tell the user to turn on "Displays have separate Spaces" and to turn OFF
      "Automatically rearrange Spaces based on most recent use" (check and show this in
      Settings; never change it without asking).
    - Borders, shadows-as-borders and dim are drawn by OUR overlay windows (borderless
      NSPanel, ignoresMouseEvents, level just above the target window via ordering
      relative to its window number), like JankyBorders. Rounded to match the 15 px
      radius, 1 px, active/inactive colors from 1.2.
    - Opacity 0.94 and blur on OTHER apps' windows are NOT possible in Standard mode.
      Panels we own get the full look.
    - Animations: our overlays and shell animate at 60/120 fps. Real windows "snap" to
      their final frame, with an optional "animated tiling" that sends interpolated AX
      frames at ≤ 60 Hz for ≤ 200 ms, off by default because many apps lag.
  ENHANCED mode (optional, needs SIP partly off, yabai-style)
    - Loads CaelestiaSA (our scripting addition) into Dock.app, so we can use the
      SkyLight/CGS private calls that need the Dock's connection: instant window move
      without AX lag, real window opacity (0.94), per-window alpha fade, scale ("popin
      80%") via transforms, window level (pin/always-on-top), sticky windows, real native
      Space create/destroy/move, focus without raising, and shadow control.
    - May reuse ideas from yabai (MIT) with attribution; do not copy GPL code.
    - Requirements (explained in docs/ENHANCED_MODE.md, never done by our tool):
        Apple Silicon: boot into Recovery (hold the power button) -> Options -> Utilities
        -> Terminal -> `csrutil enable --without fs --without debug --without nvram`,
        reboot, then in a normal Terminal run `sudo nvram boot-args=-arm64e_preview_abi`,
        reboot.
      Loading the SA needs root once per boot. Ship a sudoers drop-in TEMPLATE that the
      user may install by hand, limited to the exact SA load binary path with its
      SHA-256 checked. Our installer never writes sudoers itself, and never uses NOPASSWD
      for anything else. The default is to prompt via an authorization dialog on each
      boot.
      Revert: Recovery -> `csrutil enable` (full), reboot; `sudo nvram -d boot-args`.
    - Enhanced is never required. Every feature falls back to Standard when the SA isn't
      loaded, which is detected at runtime with a handshake and a version check (the SA
      must match the daemon build; otherwise refuse to use it and show a notice).
    - Warn clearly: lowering SIP reduces security. On a school laptop, check the school's
      rules first. macOS updates can break the SA until it's rebuilt.

4.3 Dwindle layout (copy Hyprland behavior exactly)
  - Binary tree per workspace. A new window splits the FOCUSED window's node (or the one
    under the cursor). The split direction comes from the node's aspect ratio: split
    horizontally (side by side) if width > height × 1.0 (split_width_multiplier 1.0),
    else vertically.
  - preserve_split = true: once a node has a direction, it keeps it when resized/moved.
  - smart_split = false: do not pick the split side from the cursor position; the new
    window goes right/bottom (force_split 0 = follow the mouse side only when smart_split
    is on, so effectively right/bottom).
  - smart_resizing = true: keyboard/mouse resize moves the nearest edges in the drag
    direction.
  - default_split_ratio 1.0 (50/50), the ratio range is 0.1-1.9 like Hyprland.
  - Gaps: outer 10 on every side of the usable area (20 if it's the only tiled window);
    inner 5 per window side (10 px between neighbors). Usable area = display frame minus
    the shell's reserved zones (bar width when persistent, the 10 px screen frame) minus
    the macOS menu bar/notch if it's not hidden. See 4.6 for the exact math.
  - Golden test from clients.json (5120x1440, reserved 10 each side, two windows):
    left = (21, 21, 2533x1398), right = (2566, 21, 2533x1398). Check: 10 frame + 10 gap +
    1 border = 21; 2533 + 2 border + 10 inner = 2545 = 2566 - 21; height 1440 - 2×21 =
    1398. Hyprland puts the border OUTSIDE the stored window size. On macOS the border is
    an overlay drawn just outside the frame, so the same numbers hold: the window frame is
    (21,21,2533,1398), and the overlay is (20,20,2535,1400). Encode exactly this as a unit
    test, plus 1, 3 and 4-window cases, and the same cases on 1470x956 (M4 Air 13")
    and 1710x1112 (Air 15").
  - Float rules for dialogs/sheets/panels: AXRole/AXSubrole checks (AXDialog,
    AXSystemDialog, AXFloatingWindow, sheets, popovers) are never tiled. Respect
    windows that can't resize (no AXSize settable, or min == max size): float them,
    centered.
  - Minimum sizes: if an app's minimum size makes it not fit, keep the tree but clip it
    to its min, centered in its slot, and never loop (see 12.2 retile-loop test).

4.4 Workspaces
  - 1-10 per Caelestia's group logic: "workspace N" means 10·(group-1)+N, and groups
    (Ctrl+Super+N) give 10 more per group (Caelestia wsaction: focus/move/move_silent, with
    "group" variants). Support groups up to at least 5 (50 workspaces) and say so.
  - Workspaces are per display (Hyprland default: each workspace lives on one monitor;
    focusing a workspace on another monitor moves focus there).
  - Empty workspaces vanish from the bar unless shown as "always show 1-5" (the
    Caelestia bar default: workspaces.shown 5). occupiedBg = false (Gabby).
  - Special workspace(s): "special" plus named scratchpads sysmon, music, communication,
    todo. They slide in vertically ("slidefadevert 15%") ABOVE the current workspace on
    the focused display, dimmed backdrop, NOT blurred (blur.special false). Toggling off
    slides them out. specialWsCloseAny = true (Gabby): closing via ⌥L+S works from any
    special workspace (i.e. the toggle key hides whichever special is open).
  - Workspace rules from rules.lua: gaps_out 20 when exactly one tiled window (w[tv1]
    s[false]) or one fullscreen window (f[1]s[false]); this applies on non-special
    workspaces only.
  - Persistence: remember which app window (bundle id + title + AX identifier) was on
    which workspace, and restore after WM restart; never lose windows. On quit/crash
    restore every off-screen window to a visible on-screen frame (crash-safe: a
    watchdog/launchd KeepAlive helper plus an on-disk journal of parked frames).

4.6 Displays, usable area, multi-monitor
  - Use NSScreen.frame / visibleFrame converted to one global top-left coordinate space
    (AX uses top-left origin at the primary display's top-left; AppKit uses bottom-left.
    Write ONE converter, unit-test it with displays left/right/above/below and with
    negative origins). Most "unused space" bugs come from this.
  - Usable area per display = frame − macOS menu bar height (only if the menu bar is
    shown; on notched Macs the area above the safe area is never usable:
    NSScreen.safeAreaInsets.top) − Dock (only if not auto-hidden) − our reserved zones:
    screen frame 10 px each side, plus the bar width when the bar is persistent (left
    edge). Recompute on NSApplication.didChangeScreenParametersNotification, Dock/menu-bar
    auto-hide changes, and bar show/hide.
  - Each display has its own workspace set; new displays get the next free workspace.
    Unplugging moves that display's workspaces to the remaining display, keeping their
    numbers (Hyprland behavior). Clamshell mode and sleep/wake must not lose windows.
  - Per-display overrides (like caelestia-config/monitors/DP-2/shell.json): Settings can
    set bar/gaps/scale per display by its stable id (CGDisplayCreateUUIDFromDisplayID).
  - Focus monitor: ⌥L+arrows past the last window crosses to the neighboring display
    (Hyprland movefocus behavior). Moving a window past the edge moves it to the next
    display's workspace.
  - Tested sizes: 1470x956 and 1710x1112 (Air), 1512x982 and 1728x1117 (Pro), 2560x1440
    external, 5120x1440 ultrawide (her desktop monitor, if she ever plugs it in), plus
    mixed scales (Retina laptop + 1x external).

4.7 Animation inside the WM
  - Workspace switch (Standard): slide a SNAPSHOT of the outgoing and incoming
    workspaces (ScreenCaptureKit stills, needs Screen Recording; fallback without it: a
    fast cross-fade of a solid surface-colored cover) horizontally with a 20 px gap,
    snappy curve, 320 ms, then reveal the real windows already in place. Never leave the
    snapshot up: hard timeout 600 ms and remove it on any input. No snapshot ever shows a
    black frame: if a capture isn't ready within 1 frame, skip the effect.
  - Window open: border overlay pops in from 80% with the riko spring; the real window
    snaps (Standard) or scales (Enhanced).
  - Window close: overlay fades/shrinks with emphasizedAccel 240 ms.
  - Retiling: borders follow the riko spring; real windows get one final AX setFrame
    (Standard), or frames are interpolated (Enhanced).
  - Coalesce layout: at most ONE layout pass per runloop turn / display refresh
    (CADisplayLink on macOS 14+), and changes caused by our own setFrame are tagged and
    ignored (record expected frame + timestamp; ignore AX kAXMoved/kAXResized echoes that
    match within 2 px for 250 ms).

5. NATIVE SHELL (Swift + SwiftUI/AppKit; NOT Electron, NOT a web view)
=====================================================================================
Every panel is a borderless non-activating NSPanel (or a window at a level above normal
windows, e.g. .statusBar / .popUpMenu as fits), on every display (configurable), visible on
all Spaces (collectionBehavior .canJoinAllSpaces, .stationary, .fullScreenAuxiliary),
excluded from our tiler, drawn with the scheme colors, the 0.75/0.35 transparency, and
Material 3 motion at 0.8 speed. Drawers open from screen edges like Caelestia (sliding out
of the screen frame, connected to it with concave "fillet" corners, as in the
screenshots). Panels take key focus only while they need typing (launcher, search), then
give focus back to the previous window.

5.1 Screen frame ("border" layer)
A click-through window per display, drawing the thin rounded frame (10 px band in surface
at base transparency, inner corner radius = window rounding 15 + a bit) that Caelestia
draws around the screen. It reserves 10 px each side (4.6). Toggle in Settings.

5.2 Bar (left, vertical)
  - Position LEFT edge, vertical, width ~48 pt. shell.json: persistent = false, i.e. it
    auto-hides and slides in when the pointer touches the left edge (showOnHover). Mac
    default: persistent = TRUE (a "missing bar" was a Riko complaint and macOS users
    expect a bar); one Settings switch sets "Auto-hide like Arch". When persistent, it
    reserves its width in the usable area; when auto-hidden it overlays and reserves 0.
  - Top to bottom: distro/logo button (opens launcher; use an Apple-ish or Caelestia logo,
    configurable), workspaces (pills 1..N; active = primary pill that stretches,
    occupied = dot; occupiedBg false; show 5 by default; scroll to switch; click to focus;
    special workspace indicator), active window title (rotated vertical text, app icon),
    tray (no background; macOS has no public tray API for other apps' menu extras, so show
    our own items plus an optional "menu-bar extras" button that reveals the system menu
    bar briefly; document the limit), clock (vertical "HH / MM", no background), status
    icons (shown: lock status (Caps), audio, network; hidden by default: mic, keyboard
    layout, bluetooth, battery. On a laptop, battery defaults to ON on Mac; Gabby's
    desktop had none), power button (opens session menu).
  - Hover popouts for each status icon (Wi-Fi network list, volume slider + output device,
    battery %, time remaining).
  - Data sources (public APIs only): CoreWLAN (Wi-Fi SSID needs Location permission on
    macOS 14+; fall back to "Connected" without it), CoreAudio (volume/mute/devices via
    AudioObject), IOKit power sources (battery), IOBluetooth (state), TIS input sources
    (keyboard layout), NSWorkspace (frontmost app).

5.3 Launcher (⌥L tap / ⌥L+Space)
  Bottom-center drawer as in the screenshot. Fuzzy search (fzf-like scoring over name,
  bundle name, keywords, description = Spotlight kMDItemDescription or the app's
  CFBundleGetInfoString / category) over /Applications, ~/Applications,
  /System/Applications, /System/Applications/Utilities, with icons. Frequency-weighted
  ranking. Prefix ">" for commands (Caelestia actions: >wallpaper, >scheme, >variant,

7.2 Cursor: Bibata-Modern-Classic
macOS has no public API to replace the system cursor theme. Options:
  1. (Default) Export a Mousecape-compatible .cape file. Convert the Xcursor files in
     cursor/Bibata-Modern-Classic/cursors (145 entries, many are symlinks/aliases) with a
     build-time tool: parse the Xcursor format (header "Xcur", TOC, image chunks type
     0xfffd0002 with nominal size, width, height, xhot, yhot, delay, ARGB pixels), pick
     sizes 24/48/72/96 (1x-4x), and map names to macOS cursor identifiers:
       left_ptr/default -> com.apple.coregraphics.Arrow (and .ArrowCtx)
       xterm/text -> com.apple.coregraphics.IBeam ; pointer/hand2 -> com.apple.cursor.13
       (pointing hand) ; grab/openhand -> .cursor.11 ; grabbing/closedhand -> .cursor.12
       wait/watch -> com.apple.coregraphics.Wait (animated frames: write the frame strip
       and frame count/duration) ; progress/left_ptr_watch -> .cursor.4 (busy) ;
       crosshair -> .cursor.7 ; not-allowed -> .cursor.3 ; copy -> .cursor.5 ;
       alias -> .cursor.2 ; context-menu -> its contextual-menu id. Verify EVERY identifier
       against Mousecape's documented list and include the full table in docs/CURSOR.md.
       Resize cursors: ew/ns/nesw/nwse/col/row-resize and the edge/corner cursors ->
       the matching com.apple.cursor.N windows resize ids.
     Size 24 = macOS cursor size 1.0 (the cape's PointsWide/PointsHigh 32 with hotspot
     scaled).
  2. Tell the user how to apply it with Mousecape (open source; download from its GitHub
     releases, or `brew install --cask mousecape`). Mousecape's helper uses private
     CoreGraphics APIs but needs NO SIP change. Our tool never injects into other
     processes for this.
  3. Uninstall/reset: Mousecape "Reset" (or `defaults delete com.alexzielenski.Mousecape`
     after backup), and the cape file is removed.
  Also offer macOS's built-in Accessibility cursor size + color (outline white, fill
  black is already the default) as the zero-install fallback.

10. SAFETY RULES (hard requirements)
=====================================================================================
10.1 Never destructive: no `rm -rf` on user paths, no deleting user files (use the Trash
     via NSWorkspace.recycle / FileManager.trashItem), no editing system files under
     /System, /Library (except a user-approved sudoers template the user copies by hand
     in Enhanced mode), no changes to SIP, NVRAM, boot args, firewall or MDM.
10.2 No `curl | sh` or any piped remote script, in our scripts or our docs. Downloads are
     pinned URLs + SHA-256 verified, or Homebrew. Our install script runs from a cloned
     repo/DMG.
10.3 No passwordless sudo, no sudo at all in Standard mode. install.sh and uninstall.sh
     run as the normal user. Enhanced mode's SA load uses a native authorization prompt.
10.4 Backups: before changing any `defaults` key, hidutil mapping, symbolichotkeys entry,
     wallpaper, kitty config, login item or font, record {domain, key, old value or
     "absent", new value, timestamp} in
     ~/Library/Application Support/CaelestiaMac/backup.json (append-only journal, plus a
     copy of the original plist file for symbolichotkeys). Restore writes exactly the old
     values back and verifies them.
10.5 Uninstall (one click in Settings, or `scripts/uninstall.sh`, or `caelestia
     uninstall`): stop WM, restore every off-screen window to a visible frame, restore
     every backup, remove hidutil mappings, remove the login item, unload the SA
     (Enhanced), remove our apps/CLI/fonts we installed (ask about fonts and config),
     move config to the Trash (not delete), print a report. After uninstall the Mac looks
     and behaves like stock macOS. It must work even if the WM app is already deleted
     (the script reads backup.json directly).
10.6 No stored secrets: no passwords, tokens or API keys in config or logs. Weather uses
     Open-Meteo (no key). Logs redact window titles by default (setting to include them
     for debugging).
10.7 Everything is reversible from a normal user session, without Recovery, except
     reverting Enhanced mode's SIP change, which the user did by hand and the docs explain
     how to undo.
10.8 TCC permissions (PERMISSIONS.md and the first-run wizard explain each one, why it's
     needed, what breaks without it, and how to revoke):
       Accessibility (required): read and move windows, synthesize keys.
       Input Monitoring (required for the event tap hotkeys, the ⌥L tap and ⌥L+drag;
         check with CGPreflightListenEventAccess / request with CGRequestListenEventAccess).
       Screen Recording (optional): workspace slide snapshots, screenshots, screen
         recorder, color picker, window titles of other apps on macOS 14+. Without it:
         fades instead of slides, and the capture tools are disabled.
       Automation (optional, per app): System Events for log out/restart, Spotify/Music
         for media.
       Location (optional): Wi-Fi SSID, local weather.
       Microphone (optional): recorder with mic.
     Never use tccutil to grant anything; the user grants in System Settings. Show live
     status (AXIsProcessTrusted, CGPreflight*, SCShareableContent probe).
10.9 Stable code signing so permissions survive rebuilds: TCC keys grants on the code
     signature's designated requirement. Ad-hoc signatures change every build, so grants
     are lost and the user has to remove and re-add the app (a classic Riko-style
     annoyance). Solution: `scripts/sign-setup.sh` creates a local self-signed
     code-signing certificate "Caelestia Local Signing" in the login keychain (with
     `security` and a generated config; the user sees what it does and confirms), and
     build.sh always signs every bundle with it (codesign --force --options runtime
     --sign "Caelestia Local Signing"), keeping the same bundle ids. If the friend has an
     Apple Developer ID, support that too (and notarization). Document how to delete the
     certificate on uninstall. The key never leaves the keychain and is never committed.
10.10 Fail safe: if the WM crashes, the launchd KeepAlive relaunch restores parked
     windows from the journal first. A "panic" chord (⌃⌥⌘⇧Esc, not configurable away)
     stops tiling and brings every window on-screen. The event tap has a watchdog: if it
     gets disabled by timeout (kCGEventTapDisabledByTimeout), re-enable it, and never
     block input for more than 50 ms.
10.11 School laptop note: README says to check the school's IT rules; Standard mode
     changes nothing at system level.

12.1 Unit tests (Layout, Core, Motion — no UI needed)

  - Coordinate converter: multi-display layouts incl. negative origins and the notch.
  - Rules matching; scheme generation (fixed wallpaper fixture -> expected primary within
    ΔE < 2); xcursor parser on the Bibata files.
  - Backup/restore: write, restore, verify, "absent" keys deleted.

12.2 Riko regression suite (integration; release blockers). Use a test-harness app
     (TestWindows.app: spawns N plain NSWindows with known titles and colors, some with
     min sizes, some slow to resize) and the debug IPC (`caelestia query`), plus
     ScreenCaptureKit pixel checks:
  R1 Black tiles: after open/close/switch cycles (×200), sample every tile and panel:
     no region > 32x32 px of pure #000000 that isn't in the wallpaper/test pattern; panel
     windows have non-zero alpha content within 1 frame of being shown.
  R2 Ghost overlays: after every move/close/workspace switch/display change, the set of
     our overlay windows (CGWindowList, owner = our pid) equals exactly the set of
     visible managed windows (+ shell panels). Zero leftovers after 1 s. Also after a
     killed target app (SIGKILL) and after sleep/wake.
  R3 Flashing / retile loops: in a 10 s idle window after a layout change, the WM issues
     0 AX setFrame calls and ≤ 1 layout pass; under a stubborn app that refuses its size
     (min size bigger than its slot, or an app that snaps back), layout converges in ≤ 3
     passes and then stops (no oscillation). Count passes via a debug counter.
  R4 Unused screen space: for 1/2/3/4 tiled windows on each tested display size, the
     union of window frames + gaps + borders covers the usable area exactly (± 1 px), with
     menu bar shown and hidden, Dock shown and hidden, bar persistent and auto-hidden,
     notch and no notch.
  R5 Missing bar: on launch, after display connect/disconnect, sleep/wake, Space change,
     fullscreen app enter/exit, and shell restart, the bar (when persistent) is visible
     on every display within 500 ms, above normal windows, below our panels, and at the
     correct edge.
  R6 Window safety: kill -9 the WM with windows parked; on relaunch every window is
     on-screen within 2 s. Uninstall leaves zero windows off-screen.
  Also: flicker check (no frame where a window is drawn at an intermediate wrong
  position during a workspace switch, sampled at 120 Hz on ProMotion if available) and a
  focus check (focus is never lost to "no window" after closing the focused window; it
  moves to the window under the cursor if there is one, else the next in focus history
  (Hyprland input.focus_on_close = 1).
